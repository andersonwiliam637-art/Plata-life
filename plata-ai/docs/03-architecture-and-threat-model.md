# Architecture and threat model (Phase 3)

## Chosen initial architecture
- Next.js App Router + TypeScript for server-rendered pages and app routes.
- Supabase Auth for identity and Postgres for persistence.
- Supabase browser/server clients use the publishable/anon key only; database security depends on RLS.
- No service-role key is used in the browser or this starter.
- Vercel is a deployment candidate, not deployed by this artifact.

## Trust boundaries
1. Browser: untrusted; all form inputs can be manipulated.
2. Next.js server: validates requests and performs privileged operations only when explicitly added.
3. Supabase Auth: source of identity; server-side `getUser()` is used to validate session.
4. Postgres: RLS must enforce ownership independently of UI checks.
5. Future AI provider: receives only the minimum data required; never expose API secrets client-side.

## Threats and mitigations
- Cross-user data exposure: RLS policy tied to `auth.uid()`; add tests before financial tables ship.
- Leaked service key: do not place service-role secrets in `NEXT_PUBLIC_*` variables or client bundles.
- Forged metadata: treat `user_metadata` as untrusted, constrain profile values, never use it for authorization.
- Session confusion: validate user server-side; middleware redirects are convenience, not the only security boundary.
- Receipt PII leakage: future storage must be private, access-controlled, short-lived URLs, documented retention/deletion.
- Prompt injection via receipts: treat OCR/text as untrusted input; schema-validate extracted values; do not allow receipt text to trigger tools/actions.
- Financial arithmetic errors: balances computed deterministically from validated transactions in database/server logic, not generated by an LLM.
- Abuse/cost: future AI routes need authenticated ownership checks, payload limits, per-user rate limits and cost ceilings.

## Environments
- Local: `.env.local` from `.env.example`.
- Preview: separate Supabase project or isolated data and secrets.
- Production: separate project, restricted secrets, backups, logging and rollback plan.

## Required before production
- Configure email confirmation, redirect URLs and SMTP appropriately in Supabase.
- Review database policies and trigger permissions.
- Add rate limiting, account deletion/export workflows and audit events.
- Add automated tests, dependency scanning and error monitoring.
- Define data retention, privacy notice, terms, incident response and backup restore test.
